## 5. Mutation Testing

Үндсэн кодод зориудаар 3 өөрчлөлт хийж, бичсэн тестүүд алдааг илрүүлж байгаа эсэхийг шалгасан.

### Mutation 1 — Оюутны идэвхийн нөхцөлийг өөрчлөх

Анхны код:

`if (!student.active())`

Өөрчилсөн код:

`if (student.active())`

**Үр дүн:**
- Tests run: 10
- Failures: 5
- Errors: 0
- Төлөв: KILLED

Нотолгоо: `results/mvn-test-mutant-1.txt`

### Mutation 2 — Өмнөх холбоо хичээлийн шалгалтыг өөрчлөх

Анхны код:

`if (!missing.isEmpty())`

Өөрчилсөн код:

`if (missing.isEmpty())`

**Үр дүн:**
- Tests run: 10
- Failures: 3
- Errors: 0
- Төлөв: KILLED

Нотолгоо: `results/mvn-test-mutant-2.txt`

### Mutation 3 — И-мэйлийн алдааг дамжуулах

Анхны код и-мэйл илгээх үеийн `RuntimeException` алдааг барьж, бүртгэлийг хүчинтэй хэвээр үлдээдэг.

Өөрчилсөн хувилбарт `catch` блок дотор `throw e;` нэмсэн.

**Үр дүн:**
- Tests run: 10
- Failures: 0
- Errors: 1
- Төлөв: KILLED

Нотолгоо: `results/mvn-test-mutant-3.txt`

JUnit 5 болон Mockito ашиглан хичээлийн бүртгэлийн үйлчилгээний бизнес логикийг өгөгдлийн сан болон бодит и-мэйл үйлчилгээ ашиглахгүйгээр шалгасан.

Туршилтын дараа үндсэн кодыг анхны хувилбарт сэргээж, бүх 10 тест дахин амжилттай ажилласныг баталгаажуулсан.
